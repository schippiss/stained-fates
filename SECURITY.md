# Проверка безопасности 0.1.1

Проведён обзор исходников расширения, точек сетевого доступа, сохранения данных, обработки текста и изображений, а также используемого обработчика SillyTavern release 1.19.0. Это проверка кода и локальные тесты, не независимый пентест развёрнутого сервера.

## Потоки данных

| Данные | Получатель / хранение |
| --- | --- |
| Ключ | Память текущей страницы; в запросе — сервер ST пользователя и выбранный API. В собственных постоянных хранилищах расширения не сохраняется. |
| Вопрос, ограниченные фрагменты чата, описание персонажа, сводка | Сервер ST и выбранный API для трактовки/наблюдения. |
| Предсказания, цитаты и состояние | Метаданные соответствующего чата на сервере пользователя ST. |
| Адрес API, модель, параметры | Настройки пользователя ST. |
| Пользовательские изображения | IndexedDB этого браузера и origin ST; не привязана к отдельной учётке ST, может быть общей при смене аккаунта в одном браузере. Ключей и чата там нет. |
| GitHub | Файлы расширения при установке и обновлении. Программного отправления ключей, чатов или предсказаний на GitHub/автору нет. |

Runtime содержит один `fetch`: относительный адрес `/api/backends/chat-completions/generate`. Запрос отправляется с заголовками штатного ST, включая его CSRF-защиту. Сторонних JS-зависимостей, CDN, телеметрии, выполнения кода модели и HTML-рендеринга её ответа нет. Данные выводятся через `textContent`.

## Найденное и исправленное

1. **Повторное использование ключа после смены эндпоинта.** Ранее пустое поле сохраняло предыдущий ключ даже при смене провайдера. Теперь ключ сохраняется только при точно совпадающем нормализованном адресе; смена адреса или пути требует нового ключа, иначе отправляется пустой ключ.
2. **Передача по HTTP.** Внешние API принимаются только с HTTPS. Передача ключа к самому ST через незащищённый сетевой HTTP заблокирована. Исключение — loopback. Проверены поддельные домены вида `127.evil.example` и `localhost.evil.example`.
3. **Ответы без ограничения размера.** Добавлены лимиты: 256 КиБ на тело ответа и 32000 символов на текст модели, максимум пять свидетельств на карту. Ограничение потока действует и без Content-Length. Тайм-аут — 90 секунд.
4. **Отражение фрагментов ответа в ошибке JSON.** Вместо исключений парсера выводится фиксированное сообщение без содержимого ответа. Тело ошибок HTTP не показывается пользователю.
5. **Лишние поля конфликта.** Из ответа модели сохраняются только разрешённые поля; произвольные свойства не попадают в метаданные через spread.
6. **Импорт произвольного формата под видом изображения.** Проверяются сигнатуры JPEG/PNG/WebP, лимит 23 файла за импорт и 20 МиБ на файл. После декодирования — до 24 Мп и 12000 пикселей по стороне; затем canvas-перекодирование. Это ограничивает дальнейшую обработку, но не заменяет защиту самого браузерного декодера.
7. **Управление сессией.** Добавлена явная очистка ключа и остановка наблюдения. Переходы HTTP при браузерном запросе к ST запрещены (`redirect: error`); ключ не включается в сообщения для модели.
8. **Адреса изображений из метаданных.** Допускаются только номера 0–21 и встроенная рубашка. Произвольный идентификатор не используется как путь.

## Проверки

`node --test --test-isolation=none tests/core.test.js tests/security.test.js`

Проверяются смена провайдера, HTTPS, поддельные loopback-домены, ограничение ответов, отсутствие ключа в промпте, безопасные ошибки и отбрасывание лишних полей. Браузерный сценарий `node scripts/browser-check.mjs` дополнительно проверяет инертность HTML в предсказании, отсутствие тестового ключа в настройках/метаданных, сброс ключа при смене API и отклонение SVG с именем PNG. Используются только искусственные ключи и подменённый API.

## Границы гарантий

- Расширение не контролирует владельца сервера ST, другие расширения того же сайта, расширения браузера и API-провайдера. Они входят в доверенную среду. JavaScript-память не обеспечивает криптографического удаления ключа из процесса браузера.
- В проверенном backend ST есть `console.debug('Chat Completion request:', requestBody)` и аналогичный вывод ответа. Тексты могут попасть в журналы в зависимости от конфигурации. Провайдер, прокси, администратор и резервные копии могут хранить данные. Нельзя обещать «данные нигде не хранятся».
- Код расширения не создаёт серверных маршрутов. Пользователь явно выбирает адрес API. Политика исходящих запросов и перенаправлений **с сервера ST к провайдеру** определяется ST, а не браузерным `redirect: error`. Для многопользовательского хостинга администратор должен отдельно контролировать сетевой доступ своего ST.
- Промпт-инъекция из чата может повлиять на трактовку/отметки ИИ. Текст не выполняется как код, ключ в промпт не попадает; смысловая корректность предсказания не является гарантией безопасности модели.
- Локальные проверки не подтверждают настройки TLS, журналы, изоляцию аккаунтов и безопасность конкретного хостинга. Реальный платный API и развёрнутый сервер пользователя не тестировались.
- Постоянное хранение ключа в штатном secret-хранилище ST ещё не реализовано. Его нельзя заменять записью ключа в метаданные или обычные настройки.
