# Витражи судьбы · Таро для SillyTavern

Три карты возможного будущего. Предсказание вступает в силу после выбора игрока и постепенно влияет на историю. Готическая витражная колода из 22 Старших арканов, прямые и перевёрнутые положения, оборот с предсказанием и подтверждёнными событиями. Без архива и runtime-зависимостей.

## Установка

Вход в панель — **☾ Таро** в меню волшебной палочки; плавающий полумесяц также открывает панель. Кнопка «Таро включено / выключено» останавливает запросы и влияние карт на историю, сохраняя карты. Настройки открываются отдельным экраном внутри панели.

Оформление: винный фон с локальным векторным небесным орнаментом, состаренное золото и тёмные области под текстом. Значки нарисованы в SVG, внешние шрифты и сервисы не требуются. Пункт меню использует обычный вид списка ST; плавающая кнопка учитывает видимую область мобильного экрана и клавиатуру. Изображения самих карт не изменены.

Трактовка и наблюдение используют активированные записи World Info, включая подключённые к чату лорбуки, через штатный `getWorldInfoPrompt` в режиме dry run. Книги выбирает SillyTavern по своим правилам; вся библиотека не отправляется. Дополнительный текст ограничен 10000 символами. Если метод недоступен в версии ST, запрос работает без лора. Лор служит справкой и не считается подтверждением события чата.

В корне **отдельного GitHub-репозитория** должны лежать `manifest.json`, `index.js`, `core.js`, `api.js`, `lore.js`, `style.css` и папка `assets`. Загружайте содержимое этой папки, а не весь родительский проект сайта. Исходники `КАРТЫ/`, временные файлы и результаты тестов исключены через `.gitignore`.

В SillyTavern: **Расширения → Установить расширение → URL вашего репозитория**. После установки обновите страницу. Кнопка **✧ Таро** появится в меню расширений рядом с чатом.

Для ручной установки поместите файлы в `public/scripts/extensions/third-party/stained-fates/` и перезагрузите SillyTavern. Если хотите получить чистую папку для GitHub и ZIP, запустите из этой директории `powershell -File scripts/package.ps1`. Они появятся в `test-results/release/`.

Репозиторий ещё не опубликован: сначала нужно создать его под выбранным аккаунтом. Собственный адрес обновлений берётся из Git-репозитория при установке, фиксированный URL в коде не требуется.

## Подключение модели

Ключ, адрес API и модель настраиваются штатно в SillyTavern. Таро не требует серверного плагина и не хранит собственную копию ключа.

1. В разделе API-подключений SillyTavern настройте Chat Completion и сохраните профиль подключения.
2. Откройте Таро → Настройки → «Профиль подключения SillyTavern».
3. Выберите профиль и нажмите «Сохранить настройки». После перезагрузки выбор сохраняется.
4. «Проверить подключение» отправит короткий запрос выбранной модели (провайдер может тарифицировать его).

Если профиль создан, пока Таро открыто, нажмите «Обновить список профилей». Поддерживаются профили Chat Completion с выбранной моделью. Требуется версия ST со штатным ConnectionManagerRequestService и включённым менеджером подключений. Удалённый профиль нужно выбрать заново; автоматического переключения на другую модель нет.

Запросы отправляются штатной службой ST без активации профиля и смены основного подключения чата. Таро сохраняет только ID профиля и параметры гадания. Профиль использует правила выбора ключей самого ST: это не отдельное хранилище ключа Таро. Для одного и того же провайдера ST может использовать общий активный ключ.

Управлять ключом и удалять его нужно в настройках подключений ST. Для обычных провайдеров ST использует серверное хранилище секретов; у прокси-настроек способ хранения может отличаться. Не публикуйте резервные копии пользовательских данных и экспорты с секретами. Расширение не отправляет ключи, чаты или настройки на GitHub либо автору. Контекст запроса получает выбранный API через ST.

Переход со старой версии: отдельное подключение Таро больше не используется. Создайте или выберите профиль ST. Прежний экспериментальный серверный модуль не входит в сборку; если вы устанавливали его вручную, удалите его отдельно. Пользовательские секреты расширение автоматически не удаляет.

## Гадание и наблюдение

- Задайте вопрос о предстоящем выборе. Карта выбирается локально через `crypto.getRandomValues`; ИИ не выбирает её сам. До трёх незакрытых карт, без повторов аркана.
- При трактовке отправляются последние сообщения в пределах заданного объёма, до 2500 символов описания персонажа, до 1500 символов сценария и до 2500 символов существующей памяти `extra.memory`, если она есть. Автоматического чтения всего лорбука или создания полной сводки нет. Существенную старую деталь можно добавить в вопрос.
- ИИ получает значения аркана с учётом положения. Пророчество строится прежде всего из смысла карты. Условие добровольного выбора и 2–4 критерия исполнения остаются внутренними данными, без инструкции по активации в видимом тексте.
- Сначала появляется иллюстрация карты и мягкая анимация «Читаем судьбу…». После готовности мигающий пальчик приглашает нажать на карту и перевернуть её к предсказанию и трекеру. Раскрытие «Сообщение N» показывает точную цитату, подтверждающую отметку. Настройка устройства для уменьшения движения отключает анимации.
- Модель рассказчика получает короткое условное указание на каждом ходе. До выбора последствия не должны запускаться. После выбора они обязательны по смыслу, но не имеют срока в сообщениях. Расширение не перегенерирует ответы и не принимает решения за игрока.
- По умолчанию наблюдение запускается после новых сообщений и завершения генерации. Во время генерации оно приостанавливается. Все карты объединяются в один проверочный запрос на фрагмент чата. Большие накопившиеся участки проверяются последовательными фрагментами; очень длинные сообщения делятся с перекрытием. Курсор сохраняется после проверки фрагмента.
- В экономном режиме можно проверять раз в 2–10 ответов рассказчика. Это задерживает отметки, но условие карты остаётся в промпте каждого хода. «Проверить события» перечитывает события с момента вытягивания самой ранней действующей карты и тоже расходует токены.
- Проверка возвращает номер сообщения, точную цитату и краткое описание. Код отвергает отсутствующие цитаты, события до гадания, запуск от лица рассказчика и завершение без всех критериев. **Смысловое соответствие цитаты критерию оценивает ИИ, поэтому ошибки интерпретации возможны.**
- При редактировании, удалении или смене варианта ответа хеши сообщений перепроверяются. Недействительные отметки снимаются, соответствующий участок перечитывается. Если исчезло подтверждение запуска, зависимые отметки тоже снимаются.
- Явное противоречие блокирует автоматическое исполнение и показывается в карточке. Можно исправить исходное событие в чате либо отменить предсказание. Система не переписывает его смысл.
- После исполнения карта подсвечивается и растворяется. Если её оборот открыт, эффект ждёт закрытия просмотра. Несколько исполненных карт показываются по очереди. После эффекта карта удаляется из метаданных, без архива.
- «Отменить предсказание» → «Да, отменить» удаляет карту и её дальнейшее влияние. Уже написанная история не меняется.

Если API недоступен, состояние и выбранная карта сохраняются. Неудачная трактовка повторяется для **той же карты**, без нового броска. Автоматических бесконечных повторов нет: новая проверка возможна по следующему событию или вручную.

Состояние хранится в метаданных каждого чата на сервере ST. После переключения чата старые запросы отменяются. GitHub не получает чаты или предсказания. Завершённые карты уже удалены: позднее изменение истории не восстанавливает их — это следствие отсутствия архива.

## Оформление

Встроенная колода: 23 WebP, около **3,31 МиБ**. Максимальная сторона 1100 пикселей; оригиналы сохранены отдельно в `КАРТЫ/` и не входят в пакет. Интерфейс использует системные шрифты и CSS, без CDN, видео и постоянных фоновых анимаций.

Свою колоду можно загрузить несколькими изображениями сразу в настройках. Имена `00.webp`…`21.webp`, `back.webp` либо русские названия карт. Поддерживаются JPG, PNG и WebP. «ВОЗЛЮБЛЕННЫЕ» также распознаётся как Влюблённые. Каждый файл до 20 МБ; при импорте изображения уменьшаются до 1000 пикселей и сохраняются в IndexedDB этого браузера. На другом устройстве свою колоду нужно загрузить повторно. ZIP-импорт пока не предусмотрен.

Нумерация: 00 Шут, 01 Маг, 02 Верховная Жрица, 03 Императрица, 04 Император, 05 Иерофант, 06 Влюблённые, 07 Колесница, 08 Сила, 09 Отшельник, 10 Колесо Фортуны, 11 Справедливость, 12 Повешенный, 13 Смерть, 14 Умеренность, 15 Дьявол, 16 Башня, 17 Звезда, 18 Луна, 19 Солнце, 20 Суд, 21 Мир.

## Совместимость и проверки

Интеграция написана по API ветки SillyTavern `release`, версия в проверенном исходнике — **1.19.0**. Используются `SillyTavern.getContext()`, `setExtensionPrompt`, метаданные, события чата и штатный `/api/backends/chat-completions/generate`. Установка на реальный сервер ST и платный провайдер в этой среде не проверялась. Совместимость со всеми старыми версиями не заявляется.

Интерфейс адаптивен для ПК, телефона и планшета, учитывает visual viewport, безопасные поля и уменьшение движения. Проверен в настольном Chrome при размерах 1440×1000, 390×844, 320×640, 820×1180, 1180×820, 420×900 и 390×420. Последние размеры моделируют узкое окно и открытую клавиатуру, но не заменяют проверку на реальном iPhone/iPad в Safari.

`node --test --test-isolation=none tests/core.test.js` — проверки правил и API-контракта. `node scripts/browser-check.mjs` — браузерный сценарий с подменённым API, снимки в `test-results/`. Скрипт рассчитан на Windows с Chrome в стандартной папке. Ключи и реальные платные запросы не нужны. `--assets` дополнительно пересоздаёт WebP из оригиналов через canvas браузера.

Нулевого расхода токенов и абсолютного подчинения рассказчика пророчеству гарантировать нельзя. Экономия достигается отсутствием передачи изображений, фиксированными компактными условиями, одним наблюдателем на три карты и проверкой только новых фрагментов при автоматической работе.
